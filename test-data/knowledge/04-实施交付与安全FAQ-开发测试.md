# 实施交付与安全 FAQ（开发测试）

> 数据标识：CRM-RAG-DEV-20260826。本文用于验证多文档混合检索和重排效果，不代表正式合同条款。

## 部署方式

系统可以使用 Docker 离线镜像部署。典型服务包括前端 Nginx、CRM Gateway、Java 业务服务、Python AI Runtime、PostgreSQL、Redis、Nacos、MinIO、Elasticsearch 和 Milvus。具体中间件可以使用客户已有环境，但上线前必须验证版本兼容和网络连通性。

## 配置管理

运行配置统一放入 Nacos。开发、测试和生产环境使用不同命名空间或明确的数据标识，禁止用开发配置覆盖生产配置。敏感信息不应写入前端配置、代码仓库或普通日志。

## 权限与审计

业务接口使用 JWT 身份，登录会话可以通过 Redis 共享。菜单权限决定功能入口，数据权限决定可访问的业务数据范围。线索分配、客户修改、商机操作、知识文档导入和管理员通知等关键行为应记录审计日志。

## AI 数据边界

Python AI Runtime 通过 Gateway 访问业务接口，不直接绕过业务权限读取 CRM 数据。Skills 采用渐进式加载，MCP 和 Function Calling 工具按智能体场景挂载。运行记录需要保存会话、事件、Token 用量、错误原因和节点耗时，方便后续接入可观测平台。

## 知识库处理流程

文档导入后异步执行文本清洗、标准化、切片、Embedding、Elasticsearch 写入和 Milvus 写入。检索时组合关键词召回与向量召回，再进行融合、过滤和可选重排。不同租户、知识空间、产品和索引版本必须参与过滤，避免数据串用。

## 验收建议

验收至少覆盖登录权限、线索到客户主流程、商机关联、跟进任务提醒、文件上传、AI 结构化输出、知识库重复文档处理、混合检索、服务重启和日志追踪。测试数据必须有清晰标记并与生产数据隔离。
