# 线索与客户意向产品升级说明

## 目标

本次升级为每条线索和每个客户维护一个主意向产品，保证渠道、公海、线索、客户和 AI 分析使用同一条产品上下文。

数据继承链路如下：

`渠道来源产品 → 渠道原始记录产品 → 线索意向产品 → 客户意向产品`

## 新增数据规则

- 手工新建或编辑线索时必须选择意向产品。
- Excel 导入线索前必须选择本批次统一的意向产品。
- 渠道来源必须先关联产品，缺少产品的公海数据不能晋升线索。
- 手工新建或编辑客户时必须选择意向产品。
- 线索创建新客户时，客户自动继承线索意向产品。
- 线索绑定已有客户时，产品相同则直接绑定；产品不同时必须由销售明确选择保留客户产品或使用线索产品。
- 已停用产品可以继续作为历史关联信息展示，但不能用于新的关联。

## 存量数据升级顺序

1. 备份 PostgreSQL 数据库。
2. 检查每个渠道来源是否已经关联正确产品。
3. 手工执行 `deploy/sql/manual/20260831-intended-product-backfill.sql`。
4. 查看脚本末尾输出的未关联记录和产品冲突记录。
5. 由开发人员或业务负责人手工补齐无法确定的数据，禁止按照公司名称或手机号模糊覆盖。
6. 手工执行 `deploy/sql/manual/20260831-intended-product-enforce.sql`。
7. SQL 全部成功后再发布本次应用代码。

## 回填原则

- 只填充空的 `product_id`，不覆盖已经存在的产品。
- 一个对象只能确定出唯一产品时才自动回填。
- 同一客户关联多个不同产品的历史线索时保留为冲突，由业务负责人确定主意向产品。
- 无渠道关系、无转化关系的数据不会猜测产品，需要手工补齐。
- 应用启动阶段不会执行任何历史表结构兼容或自动迁移逻辑。
