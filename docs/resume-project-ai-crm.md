# 智能营销管理系统项目简历说明

## 一、背景

传统 CRM 更多用于客户资料登记、销售过程记录和基础报表统计，对市场渠道、线索质量、客户跟进、商机推进和 AI 辅助分析的支撑不足。实际销售过程中存在几个问题：

- 渠道来源分散，表单、电话、微信、线下活动、音视频和沟通纪要等材料难以统一沉淀。
- 线索转客户、客户转商机、商机关联产品和跟进记录之间缺少完整闭环。
- 权限体系粗糙，菜单权限和数据权限难以支撑企业级组织架构。
- AI 能力容易被写死在业务代码中，缺少场景化提示词、工具、MCP、Token 用量和执行过程可观测能力。
- 公司产品资料、解决方案、客户案例和客服问答缺少统一知识库，无法稳定支撑销售助手、获客表单和客服机器人。
- 部署环境存在内网、离线交付、客户侧中间件复用等要求，需要一套可落地的工程化部署方案。

本项目定位为从传统 CRM 演进到 AI CRM 的智能营销管理系统，围绕“渠道获客、线索识别、客户运营、商机推进、知识库增强、AI 分析、权限治理、部署交付”构建完整业务闭环。

## 二、个人角色

主要职责：

- 负责 React 前端后台管理端建设，包括页面布局、主题适配、路由封装、接口封装、权限渲染、列表/抽屉/弹窗/富文本等通用组件。
- 负责后端核心业务能力，包括初始化安装、超级管理员、组织部门、角色权限、菜单权限、数据权限、用户管理、客户、线索、渠道、商机、跟进记录和大模型配置。
- 负责 AI AgentRuntime 设计和接入，支持按业务场景动态加载智能体、提示词、Skills、MCP 服务和工具调用。
- 负责线索 AI 分析、客户深度总结、客户公开信息检索、结构化结果输出、Token 用量控制和执行事件记录。

- 负责 Python AI Runtime 原型落地，搭建 FastAPI + LangGraph 编排流程，为复杂工作流、多智能体编排、Checkpoint 和 LangSmith Trace 接入保留扩展路径。
- 负责 Docker 离线部署包、Jenkins Pipeline、Nginx 代理、后端服务、前端静态资源和 AI Runtime 的交付方案。

## 四、项目部分

### 1. 使用 DDD 和 Maven 多模块拆分系统边界

项目按领域能力拆分为 `crm-domain`、`crm-application`、`crm-web`、`crm-auth`、`crm-agent-runtime`、`crm-agent-web`、`crm-common`、`crm-observability`、`crm-activity`、`crm-knowledge` 等模块。

解决的问题：

- 避免传统后台系统中 Controller、Service、DAO 混杂导致后期难维护。
- 将认证权限、业务应用、领域模型和 AI 运行时隔离，降低模块耦合。
- 为后续扩展工作流、知识库、AI Agent 和外部系统集成保留清晰边界。

亮点：

- JPA 仅用于实体 DDL 初始化和表结构演进，业务查询、分页、增删改统一走 MyBatis-Plus。
- 通过应用层作为事务入口，领域层沉淀实体、枚举、Mapper 和核心模型，接口层只负责请求入口和参数转换。

### 2. 重建企业级权限体系

系统实现了超级管理员初始化、租户根部门、组织部门、用户、角色、菜单权限、功能权限和数据权限。

解决的问题：

- 首次安装时无管理员无法进入系统的问题。
- 不同角色只能访问授权菜单和功能。
- 销售、主管、管理员之间可以按本人、本部门、全公司等范围控制数据可见性。

亮点：

- 初始化安装时检测是否存在超级管理员，不存在则进入初始化页面创建超级管理员。
- 菜单权限和数据权限支持按模块勾选，减少人工填写权限编码。
- 前端基于权限结果控制菜单、按钮和页面入口，后端通过 Spring Security 做接口权限保护。

### 3. 打通 CRM 主业务闭环

系统完成了渠道、线索、客户、商机、产品、跟进记录之间的核心链路。

解决的问题：

- 渠道数据无法沉淀为线索。
- 线索转客户缺少标准流程。
- 客户、商机、产品和跟进记录之间缺少联动。
- 销售过程只记录结果，不记录互动过程。

亮点：

- 渠道管理支持手动创建、获客表单、音视频导入和文档/HTML 导入。
- 线索支持状态流转、AI 分析、转客户和跟进记录。
- 客户详情支持完整信息、商机、跟进时间轴和 AI 客户深度总结。
- 商机支持关联客户和产品，为后续报价、合同和回款模块预留空间。
- 跟进记录接入富文本编辑器，支持图文内容，为真实销售沟通沉淀上下文。

### 4. 支持渠道材料导入并转化线索

渠道管理新增文档和 HTML 页面导入能力，可上传老板沟通纪要、客户访谈记录、会议纪要等材料。

解决的问题：

- 销售或老板手里的非结构化沟通材料无法直接进入 CRM。
- 手工整理联系人、诉求、风险、下一步动作成本高。
- 后续线索转化缺少上下文。

亮点：

- 后端支持 HTML、TXT、MD、DOCX 文档解析。
- 自动提取联系人、公司、电话、邮箱、客户分级、技术现状、核心诉求、顾虑和下一步动作。
- 导入后先形成渠道记录，再通过“晋升线索”进入线索池，保留原始材料和结构化摘要。
- 对无法明确识别的信息保持为空，不伪造客户数据。

### 5. 设计 AI AgentRuntime，可动态编排提示词、工具、Skills 和 MCP

系统在 `crm-agent-runtime` 中封装统一 AgentRuntime，业务侧通过 `crm-agent-web` 暴露智能体配置和运行入口。

解决的问题：

- AI 能力如果直接写在业务 Service 中，会导致提示词、工具和模型配置无法动态调整。
- 不同业务场景需要不同智能体，比如线索分析、客户总结、公开信息检索和营销助手。
- AI 执行过程需要可观测、可追踪、可统计成本。

亮点：

- 支持按场景加载智能体配置，隔离不同场景的系统提示词和上下文。
- 支持动态挂载 Skills 和 MCP 服务，避免工具能力硬编码。
- 支持 Function Calling 约束模型输出结构，提升线索分析结果稳定性。
- 设计 `agents`、`agent_run`、`agent_events`、`conversation` 等表记录智能体、运行实例、事件流和会话。
- 对 Token 使用做日维度统计和额度限制，为后续 AI 用量大盘、成本控制和审计分析打基础。

### 6. 引入 LangGraph 作为 Python AI Runtime 编排方案

项目保留 Java AgentScope 主链路，同时新增独立 `crm-ai-runtime` Python 模块，用 FastAPI 暴露内部接口，用 LangGraph 组织线索 AI 分析流程。

解决的问题：

- Java 侧适合业务闭环和权限治理，但复杂多智能体编排、Checkpoint、Trace 和 Python 生态工具集成更适合独立 AI Runtime。
- 后续如果需要 RAG、网页解析、企业信息检索、多步骤推理和模型评估，需要更灵活的 AI 编排层。

亮点：

- 使用 FastAPI 独立部署 AI Runtime，不直接暴露给前端和公网，由 Java 侧 `crm-agent-web` 做统一代理。
- 使用 LangGraph StateGraph 组织“读取线索上下文、客户公开信息检索、结构化分析、结果整理”等节点。
- 预留 LangGraph Checkpoint PostgreSQL，用于持久化图执行状态。
- 预留 LangSmith Trace，用于观察节点执行、模型调用、工具调用和耗时。
- 形成 Java AgentScope 与 Python LangGraph 双 Runtime 兼容方案，后续可按场景平滑迁移。

### 7. 设计 RAG 知识库，打通销售、获客表单和客服机器人

系统规划独立 `crm-knowledge` 模块作为知识库接入层，用于沉淀公司产品资料、解决方案、客户案例、FAQ、销售话术、交付文档和历史跟进记录。

解决的问题：

- 销售对产品能力、方案边界、竞品差异和客户案例的回答依赖人工经验，标准化程度不高。
- 获客表单只能收集客户信息，无法结合产品知识做即时引导和线索质量判断。
- 客服机器人如果只依赖大模型通用知识，容易产生幻觉，无法回答公司真实产品和服务细节。
- 客户、线索、商机和跟进记录中的上下文没有进入 AI 检索链路，AI 输出容易脱离真实业务。

亮点：

- 设计统一知识库入口，支持后续导入产品文档、官网内容、解决方案、客户案例、FAQ 和销售 SOP。
- 预留文档解析、文本切片、Embedding、向量检索、关键词检索和结果重排链路。
- 知识库结果可作为 AgentRuntime 的工具能力或 LangGraph 节点挂载到不同场景。
- 线索分析时可结合客户公开信息、公司产品知识和历史跟进记录，生成更贴近销售动作的建议。
- 获客表单后续可根据客户填写内容实时匹配产品方案，辅助判断线索优先级。
- 客服机器人后续可基于 RAG 回答产品介绍、部署方式、价格策略、常见问题和售后流程，降低人工客服压力。

### 8. 接入真实数据大盘和 AI 分析结果

工作台、客户、线索、渠道、商机等页面均按真实接口接入，避免使用伪造数据。

解决的问题：

- 页面展示与后端数据脱节。
- 销售无法从首页快速看到真实业务状态。
- AI 分析结果如果只展示文本，不利于销售抓重点。

亮点：

- 工作台展示真实线索状态、客户数量、商机数据和渠道转化。
- AI 分析结果按销售视角展示关键结论、置信度、建议动作、风险提醒和客户档案。
- 前端对长整型 ID 做精度保护，避免雪花 ID 在浏览器中丢失精度。

### 9. 完成离线部署和工程化交付

项目提供 Docker Compose、Nginx 配置、Jenkins Pipeline 和离线部署包脚本。

解决的问题：

- 客户侧环境可能无法联网，不能依赖在线拉镜像和在线安装依赖。
- 前端、后端、AI Runtime 和中间件需要统一部署。
- 老版本运行时需要支持可控升级。

亮点：

- Jenkins 只需指定分支即可构建离线包。
- 离线包统一命名为 `crm-分支-release.tar.gz`，方便归档和部署。
- Docker Compose 编排前端、后端、PostgreSQL、Redis、MinIO、AI Runtime 等服务。
- 前端通过 Nginx 统一代理 `/api`、`/uploads`、`/minio` 等路径，降低跨域和部署复杂度。

## 五、简历短版写法

项目名称：智能营销管理系统（AI CRM）

项目描述：

基于 Spring Boot 4、React、PostgreSQL 和 AgentScope 构建的 AI CRM 系统，覆盖渠道获客、线索识别、客户管理、商机推进、跟进记录、RAG 知识库、权限治理、AI 分析和离线部署。系统通过 DDD 多模块拆分业务边界，引入 AgentRuntime 支持场景化智能体、提示词注入、Skills/MCP 动态挂载、Function Calling 结构化输出和 Token 用量控制，同时落地 FastAPI + LangGraph 独立 AI Runtime 原型，为复杂多智能体编排、Checkpoint 和 LangSmith Trace 接入提供扩展能力。

个人职责：

- 负责系统 DDD 架构设计和 Maven 多模块拆分，建设领域层、应用层、Web 层、认证权限、AgentRuntime 和部署模块。
- 负责 React 管理端开发，封装路由、接口、布局、表格、抽屉、弹窗、富文本和权限组件。
- 负责用户、组织、角色、菜单权限、数据权限、客户、线索、渠道、商机、产品和跟进记录等核心模块开发。
- 负责 AgentRuntime 设计，实现按场景加载智能体、提示词、Skills、MCP 和工具调用，并记录运行事件、会话和 Token 用量。
- 负责线索 AI 分析、客户深度总结和客户公开信息检索，使用 Function Calling 约束结构化输出，提升销售决策可读性。
- 负责 RAG 知识库方案设计，规划产品资料、解决方案、客户案例、FAQ、销售 SOP 和跟进记录的统一检索增强能力。
- 负责 FastAPI + LangGraph AI Runtime 原型落地，设计线索分析图流程、Checkpoint 和 LangSmith Trace 接入方案。
- 负责 Docker 离线部署包和 Jenkins Pipeline，支持内网环境一键构建和部署。

项目亮点：

- 设计企业级 RBAC + 数据权限体系，支持超级管理员初始化、租户根部门、菜单权限、功能权限和数据范围控制。
- 将渠道、线索、客户、商机、产品和跟进记录打通，形成从获客到销售推进的完整业务闭环。
- 支持文档、HTML、音视频和获客表单等多渠道线索沉淀，能从沟通纪要中提取客户画像、诉求、风险和下一步动作。
- 封装独立 AgentRuntime，支持智能体场景化配置、工具动态挂载、事件流记录、Token 限额和 AI 成本治理。
- 设计 RAG 知识库能力，将公司产品知识、客户上下文、获客表单和客服机器人打通，降低 AI 幻觉并提升销售回答准确性。
- 落地 LangGraph 独立 AI Runtime 原型，通过 Java 代理统一 API，为复杂多智能体工作流和可观测能力升级预留空间。
- 提供 Docker Compose 和离线部署方案，解决客户内网环境交付和版本升级问题。
